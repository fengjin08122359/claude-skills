# 需求变更检测规则

## 判断检查清单（必须全部回答）

| 检查项 | 类型A（独立新需求） | 类型B（修改当前需求） |
|--------|-------------------|---------------------|
| 共享核心组件？ | 不共享 | 共享 |
| 同一数据流？ | 独立数据流 | 同一数据流 |
| 同一迭代完成？ | 可独立交付 | 需要协同 |
| 业务目标独立？ | 独立 | 同一目标 |

**判断规则：**
- 全部回答"是" → 类型A（独立新需求）
- 任意回答"否" → 类型B（修改当前需求）

## 类型A：独立新需求

**特征：** 不共享文件依赖、独立业务目标、独立技术实现

**处理：**
1. 告知用户检测到新需求，建议先完成当前任务
2. 完成当前流程
3. 流程结束后提醒开启新流程

## 类型B：修改当前需求

**特征：** 补充/细化/修正当前需求、共享文件依赖

**处理：**
1. 合并需求描述
2. 重新执行阶段0（影响范围分析）
3. 重新评分复杂度（只针对合并后需求评判，不累加）
4. 重新执行阶段1

## 常见判断案例

| 用户回复 | 类型 | 处理 |
|---------|------|------|
| "顺便加个搜索功能" | A | 完成当前 → 新流程 |
| "列表还需要支持排序" | B | 合并 → 重新分析 |
| "修复登录bug" → "顺便优化注册" | A | 完成当前 → 新流程 |
| "修复登录bug" → "显示验证码" | B | 合并 → 重新分析 |
