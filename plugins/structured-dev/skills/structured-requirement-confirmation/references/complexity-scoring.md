# 复杂度评分指南

## 5 维度评分

| 维度 | 1分 | 3分 | 5分 |
|-----|-----|-----|-----|
| 文件数量 | 1-2个 | 3-5个 | 6+个 |
| 依赖复杂度 | 独立模块 | 2-3模块交互 | 4+模块或核心架构 |
| 需求明确度 | 非常清晰 | 2-3模糊点 | 4+模糊点 |
| 技术风险 | 常规实现 | 新技术或重构 | 架构变更 |
| 业务复杂度 | 简单增删改 | 业务规则变更 | 核心流程 |

**总分 = 文件 + 依赖 + 需求 + 技术 + 业务**

## 评分规则（来自 config/difficulty-rules.yaml）

### 额外加分项

| 条件 | 加分 |
|------|------|
| 涉及多个版本/分支合并 | +2 |
| 需要保留现有功能 | +1 |
| 需要引入新架构 | +3 |
| 需要兼容性测试 | +2 |
| 有详细迁移计划文档 | -1 |
| 有 PRD 文档 | -1 |

### 难度等级

| 总分 | 难度 | 处理策略 | 测试要求 |
|-----|------|---------|---------|
| ≤10分 | 低 | 直接拆分 | TDD + 功能验证 |
| 11-15分 | 中 | 澄清后拆分 | TDD + 集成测试 |
| ≥16分 | 高 | 拆分子需求 + 确认 | **必须单元测试** + TDD |

## 重要规则

- **不累加评分** — 多个需求合并时重新评估
- **只对独立需求评判** — 一个需求只评分一次
- **需求合并时重新评分** — 类型B变更时重新评估

## 评分分支策略

- ≤10分：提出 2-3 个问题
- 11-15分：提出 3-5 个问题
- ≥16分：强烈推荐 Plan Agent
