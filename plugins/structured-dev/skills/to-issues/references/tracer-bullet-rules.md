# Tracer-Bullet 纵向切片规则

## 核心概念

**Tracer Bullet（追踪弹）** 是一种开发方法：创建一个薄的纵向切片，贯穿所有层，证明路径可行。

## 切片规则

1. **每个切片都是完整的端到端路径**
   - 穿过 schema、API、UI、tests 所有层
   - 不是水平切片（不是"先做所有 API"）

2. **完成的切片可演示或验证**
   - 切片完成后，功能可运行
   - 用户可以看到效果

3. **宁可多而薄，不要少而厚**
   - 多个小切片 > 少个大切片
   - 每个切片更容易理解和测试

## HITL vs AFK

| 类型 | 说明 | 示例 |
|------|------|------|
| **AFK** | 可自主完成和合并 | 添加 API 端点、编写测试 |
| **HITL** | 需要人工交互 | 架构决策、设计评审 |

**优先 AFK，减少 HITL。**

## 切片示例

### 错误做法（水平切片）

```
1. 创建所有数据库表
2. 编写所有 API 端点
3. 创建所有 UI 组件
4. 编写所有测试
```

### 正确做法（纵向切片）

```
切片1: 用户登录 → 数据库验证 → API → 前端表单 → 登录测试
切片2: 用户注册 → 数据库创建 → API → 前端表单 → 注册测试
切片3: 密码重置 → 邮件发送 → API → 前端链接 → 重置测试
```
