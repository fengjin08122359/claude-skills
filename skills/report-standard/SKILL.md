# 报告规范化标准

本 skill 定义项目中所有技术报告的标准格式和结构，确保报告的一致性、可读性和专业性。

## 核心原则

### 1. 结构化层次
所有报告必须遵循清晰的层次结构：
- **标题层级**: H1 → H2 → H3 → H4（不超过4层）
- **逻辑顺序**: 摘要 → 详情 → 结论 → 建议
- **视觉分隔**: 使用水平线 `---` 分隔主要章节

### 2. 信息密度平衡
- ** executive summary**: 首段提供关键信息概览
- **渐进式披露**: 重要信息前置，细节后置
- **可视化辅助**: 适当使用表格、列表、代码块

### 3. 一致性规范
- **术语统一**: 全文使用一致的技术术语
- **格式统一**: 相同的元素使用相同的格式
- **风格统一**: 保持语气和专业度一致

## 格式规范细则

### 1. 标题规范

**H1 (#)**: 报告主标题
- 简洁明了，体现核心内容
- 示例: `# Service 层重构完成报告`

**H2 (##)**: 主要章节
- 使用 emoji 增强可读性
- 示例: `## 📊 执行摘要`, `## ✅ 完成的工作`

**H3 (###)**: 子章节
- 具体分类或条目
- 示例: `### 高优先级问题`, `### 代码质量指标`

**H4 (####)**: 详细条目
- 具体问题或项目
- 示例: `#### 1. 使用了 any 类型`

---

### 2. 列表规范

**无序列表**: 使用 `-` 而非 `*`
```markdown
- 项目1
- 项目2
  - 子项目2.1
  - 子项目2.2
```

**有序列表**: 仅在顺序重要时使用
```markdown
1. 第一步
2. 第二步
3. 第三步
```

**任务列表**: 用于进度跟踪
```markdown
- [x] 已完成
- [ ] 待完成
- [-] 进行中
```

---

### 3. 代码块规范

**带语言标识**:
````markdown
```typescript
const value: string = "hello";
```
````

**突出差异**:
````markdown
```diff
- const data: any = fetchData();
+ interface UserData { id: string; }
+ const data: UserData = fetchData<UserData>();
```
````

**命令行**:
````markdown
```bash
pnpm vue-tsc --noEmit
```
````

---

### 4. 表格规范

**基本表格**:
```markdown
| 列1 | 列2 | 列3 |
|------|------|------|
| 值1 | 值2 | 值3 |
```

**对齐方式**:
```markdown
| 左对齐 | 居中对齐 | 右对齐 |
|:-------|:--------:|-------:|
| 值1 | 值2 | 值3 |
```

---

### 5. 引用和强调

**重要提示**:
```markdown
> ⚠️ **注意**: 这是重要提示信息
```

**强调文本**:
- **粗体**: 关键术语、状态
- *斜体*: 文件名、变量名
- `行内代码`: 代码元素

---

**状态标识**:
- ✅ 成功/完成
- ❌ 失败/错误
- ⚠️ 警告/注意
- ℹ️ 信息/说明
- 🔴 高优先级
- 🟡 中优先级
- 🔵 低优先级

**章节标识**:
- 📊 数据统计
- 🔍 问题分析
- 📈 改进成果
- 🛠️ 技术方案
- 📋 任务清单

## 常见错误及避免

### ❌ 错误 1: 标题层级跳跃
```markdown
# H1
### H3  # 错误：跳过了 H2
```

**✅ 正确**:
```markdown
# H1
## H2
### H3
```

---

### ❌ 错误 2: 代码块缺少语言标识
````markdown
```
const x = 1;
```
````

**✅ 正确**:
````markdown
```typescript
const x = 1;
```
````

---

### ❌ 错误 3: 表格不对齐
```markdown
|列1|列2|
|--|--|
|值1|值2|
```

**✅ 正确**:
```markdown
| 列1 | 列2 |
|------|------|
| 值1 | 值2 |
```

---

### ❌ 错误 4: 过长的段落
```markdown
这是一个非常长的段落，包含了太多的信息，没有适当的分段，
使得阅读变得困难，读者很难快速找到关键信息，应该将其分解
为多个短段落或使用列表形式来呈现。
```

**✅ 正确**:
```markdown
这是一个简短的段落。

关键点：
- 要点1
- 要点2
- 要点3
```

## 自动化检查

### 使用工具验证

```bash
# 检查 Markdown 格式
npx markdownlint reports/*.md

# 检查链接有效性
npx markdown-link-check reports/*.md

# 检查拼写
npx cspell reports/*.md
```

### 配置 markdownlint

创建 `.markdownlintrc`:
```json
{
  "default": true,
  "MD013": false,
  "MD024": { "siblings_only": true },
  "MD033": false
}
```

## 最佳实践

### 1. 先写摘要，再写详情
让读者可以快速了解核心内容，再决定是否深入阅读。

### 2. 使用数据支撑观点
避免主观判断，用具体数据说话。

### 3. 提供可操作的建議
每个问题都应配有具体的解决方案。

### 4. 保持客观中立
使用事实性语言，避免情绪化表达。

### 5. 定期更新和维护
报告应反映最新状态，过时信息要及时更新。
