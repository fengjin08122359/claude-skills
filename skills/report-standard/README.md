# Report Standard Skill

规范化报告生成的格式和形式，确保所有技术报告、进度报告和性能分析报告具有一致的高质量标准。

## 📋 功能特性

- ✅ **3种标准模板**: 技术分析、项目进度、性能分析
- ✅ **详细格式规范**: 标题、列表、代码块、表格等
- ✅ **质量控制清单**: 确保报告完整性
- ✅ **自动化检查工具**: Bash 和 PowerShell 脚本
- ✅ **丰富示例库**: 5个完整示例供参考

## 🚀 快速开始

### 1. 选择报告模板

根据报告类型选择合适的模板：

```markdown
# 技术分析报告
适用于：代码审查、重构总结、问题诊断

# 项目进度报告  
适用于：任务完成、阶段性总结、里程碑报告

# 性能分析报告
适用于：性能优化、瓶颈分析、基准测试
```

### 2. 填充内容

按照模板结构，替换占位符为实际内容：

```markdown
## 📊 执行摘要

**执行时间**: 2026-04-16  
**执行状态**: ✅ 完成  
**总耗时**: 2 小时  
```

### 3. 质量检查

运行检查脚本验证报告质量：

```bash
# Linux/Mac
bash scripts/check-report.sh your-report.md

# Windows PowerShell
.\scripts\check-report.ps1 your-report.md
```

## 🎯 核心原则

### 1. 结构化层次
- H1 → H2 → H3 → H4（不超过4层）
- 摘要 → 详情 → 结论 → 建议
- 使用水平线 `---` 分隔章节

### 2. 信息密度平衡
- 首段提供关键信息概览
- 重要信息前置，细节后置
- 适当使用表格、列表、代码块

### 3. 一致性规范
- 术语统一
- 格式统一
- 风格统一

## ✨ 格式规范要点

### 标题层级
```markdown
# H1 - 报告主标题
## H2 - 主要章节（带 emoji）
### H3 - 子章节
#### H4 - 详细条目
```

### 代码块
````markdown
```typescript
// 带语言标识
const value: string = "hello";
```

```diff
// 突出差异
- const data: any = fetchData();
+ const data: UserData = fetchData<UserData>();
```
````

### 表格
```markdown
| 列1 | 列2 | 列3 |
|------|------|------|
| 值1 | 值2 | 值3 |
```

### 列表
```markdown
- 无序列表项
  - 嵌套项

1. 有序列表项
2. 第二项

- [x] 已完成
- [ ] 待完成
```

## 💡 最佳实践

### 1. 先写摘要，再写详情
让读者可以快速了解核心内容。

### 2. 使用数据支撑观点
避免主观判断，用具体数据说话。

### 3. 提供可操作的建议
每个问题都应配有具体的解决方案。

### 4. 保持客观中立
使用事实性语言，避免情绪化表达。

### 5. 定期更新和维护
报告应反映最新状态，过时信息要及时更新。
