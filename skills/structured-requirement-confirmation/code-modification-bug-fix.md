## 步骤1：问题定位分析

基于阶段0的链路分析和阶段1的问题澄清，**重新整理**问题定位信息。

### 1.1 汇总问题信息

整合阶段0和阶段1的信息：

```markdown
## 🔍 问题信息汇总

**Bug描述（阶段0）：** [问题描述]
**具体表现（阶段1确认）：** [用户确认的具体表现]
**预期行为（阶段1确认）：** [用户确认的预期行为]
**触发条件（阶段1确认）：** [用户确认的触发条件]

**影响范围（阶段0分析）：**
- 直接影响：[fileA.ts] - 核心问题文件
- 连带影响：[fileB.ts] - 调用方
- 潜在影响：[fileC.ts] - 可能存在同类问题
```

### 1.2 定位具体错误位置

基于汇总信息，定位到具体的代码位置：

```markdown
## 📍 错误位置定位

**目标文件：** [bugFile.ts]

| 位置 | 代码片段 | 问题分析 |
|-----|---------|---------|
| L45-50 | `if (data.status === 'success')` | 条件判断错误，应判断 'completed' |
| L78 | `return result` | 缺少错误处理，result可能为null |
| L120 | `fetchData().then(...)` | 异步处理顺序问题 |

**根因确定：** [具体根因描述]
```

### 1.3 制定修复策略

基于定位结果制定修复计划：

```markdown
## 📋 修复策略

| 序号 | 文件 | 修复类型 | 具体操作 | 状态 |
|-----|------|---------|---------|-----|
| 1 | [bugFile.ts:L45] | 条件修复 | 将 'success' 改为 'completed' | ⏳ |
| 2 | [bugFile.ts:L78] | 空值处理 | 添加 null 检查，返回默认值 | ⏳ |
| 3 | [bugFile.ts:L120] | 异步修复 | 调整 async/await 顺序 | ⏳ |
| 4 | [relatedFile.ts] | 连带修复 | 同类问题排查（如有） | ⏳ |
| 5 | [bugFile.test.ts] | 测试补充 | 新增Bug复现测试 | ⏳ |
```

## 步骤2：最小化修复

### 2.1 执行根因修复

**最小化修改原则**：只改必要的代码，不重构、不添加新功能

```markdown
## 🔧 根因修复执行

**修复1：** bugFile.ts:L45

| 修复前 | 修复后 | 修改原因 |
|-------|-------|---------|
| `if (data.status === 'success')` | `if (data.status === 'completed')` | 阶段1确认正确状态值为 'completed' |

**修复2：** bugFile.ts:L78

| 修复前 | 修复后 | 修改原因 |
|-------|-------|---------|
| `return result` | `return result ?? defaultValue` | 阶段1确认需要空值兜底 |

**修复记录：**
```typescript
// bugFile.ts 修复后代码片段
if (data.status === 'completed') {  // 🔧 已修复
  return result ?? defaultValue;    // 🔧 已修复
}
```
```

### 2.2 验证修复有效

运行Bug复现测试：

```markdown
## ✅ 修复验证

**复现测试：** 使用阶段1确认的触发条件测试
- 触发条件：[阶段1确认的条件]
- 测试结果：✅ Bug不再复现

**回归测试：** 确认修复不破坏现有功能
- 现有测试：✅ 全部通过
- 手动验证：✅ 正常流程无异常
```

### 2.3 失败处理

若修复无效，回到步骤1重新定位：

```markdown
## ❌ 修复失败处理

若复现测试仍失败：
1. 回到步骤1.2重新定位错误位置
2. 检查是否有其他根因（多重问题）
3. 重新制定修复策略
4. 再次执行步骤2
```

## Bug修复陷阱提醒

| 陷阱 | 正确做法 |
|-----|---------|
| 未汇总直接修复 | 步骤1必须整合阶段0+阶段1信息，定位具体位置 |
| 修复时顺便重构 | 步骤2只修复必要代码，重构应分离处理 |
| 遗漏阶段1确认项 | 对照阶段1问答清单，确保所有确认点已处理 |
| 无复现测试 | 步骤3必须新增复现测试，否则无法验证有效性 |
| 忽略连带排查 | 步骤3.3排查同类问题，防止遗漏 |

---

## 特殊情况处理

### 快速止血 vs 根因修复

| 场景 | 策略 | 处理方式 |
|-----|------|---------|
| 紧急线上问题 | 先止血 | 步骤2临时修复 + 标记FIXME，后续根治 |
| 开发阶段Bug | 直接根治 | 完整执行步骤1→2→3 |
| 影响面广的Bug | 根治+排查 | 步骤3.3全面排查同类问题 |

### 临时修复标记

```typescript
// FIXME: 临时修复 - 2024-01-15 - 等待重构xxx模块根治
// TODO: 需要重构XXX模块彻底解决，避免硬编码状态值
```
