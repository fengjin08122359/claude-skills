## 新需求陷阱提醒

| 陷阱 | 正确做法 |
|-----|---------|
| 未拆分直接开发 | 步骤1必须输出模块拆分，明确文件职责 |
| 跳过骨架直接实现 | 步骤2先创建骨架，确保类型约束正确再填充 |
| 上层先于下层 | 严格按执行顺序：类型→API→状态→UI→集成 |
| 遗漏阶段1确认项 | 步骤3对照阶段1问答清单逐项实现 |
| 新功能破坏旧功能 | 每步运行现有测试，确认无回归 |
