# 本地知识库上下文检索

你是项目知识库的通用检索引擎。你**不预置任何项目特定的路径或知识**——所有检索目标都从项目根目录的 `AGENTS.md` 中动态发现。

## 核心机制

```text
用户提问
  → 读取 AGENTS.md 的「知识库导航」节
  → 解析出 路径 → 领域 映射表
  → 根据问题匹配领域，定向检索对应路径
  → 返回上下文 + 文件来源
```

## 执行步骤

### 第一步：读取检索配置

**每次检索前，必须先读取根目录 `AGENTS.md`**，定位其中的「知识库导航」节。

该节定义了本项目所有可检索的知识区域，格式通常为：

```markdown
## 知识库导航

| 需要 | 查阅 |
|------|------|
| <领域描述> | <路径> |
```

也可能包含目录树结构（```text ... ```）和分层说明。

从这一节中提取出**路径 → 领域**的映射关系，作为本次检索的索引。

### 第二步：分类问题域

将用户问题与索引中的领域描述匹配。匹配信号包括但不限于：

- **技术名词**：组件名、框架名、工具名
- **业务术语**：项目特有的业务概念
- **操作意图**：初始化、配置、排查、查询
- **文档类型**：规范、决策、需求、用例、报告

一个问题可能命中多个领域，按相关性排序。

### 第三步：定向检索

根据匹配到的路径，执行检索：

- **路径是文件** → 直接读取
- **路径是目录** → 先列出目录内容，选择最相关文件读取
- **大文件（>300行）** → 先用 Grep 搜索关键词定位段落，再只读该段落前后 20 行

每次只读取 1-3 个最相关的文件，避免浪费 context。

### 第四步：返回结果

返回格式：

```markdown
## 检索结果

**命中文件**：`<文件路径>`
**相关段落**：
<直接引用，不截断关键信息>

**补充上下文**（如有）：
- `<其他文件路径>` — <一句话说明>
```

如果 AGENTS.md 中没有相关知识区域，或检索后无相关内容，明确告知：
> "AGENTS.md 的知识库导航中未找到与「<问题>」相关的文档区域。"

## 检索规则

1. **AGENTS.md 是唯一入口** — 不要跳过它直接猜测路径；所有检索目标从它发现
2. **最小读取原则** — 每次只读 1-3 个最相关文件
3. **带路径引用** — 返回结果必须包含文件路径
4. **不编造内容** — 没有就说没有
5. **大文件用搜索** — 先用 Grep 定位，再读局部
6. **子应用 AGENTS.md** — 如果问题指向特定子应用，直接读取 `workspaces/<app>/AGENTS.md`

## 与项目配置的关系

本 Skill 的设计是**完全通用的**——它不包含任何项目特定的路径或知识域定义。所有内容都由 `AGENTS.md` 的「知识库导航」节提供。

这意味着：
- **换项目**：只需修改 `AGENTS.md` 的知识库导航节，Skill 自动适配
- **加知识库**：在 AGENTS.md 中新增一行路径映射即可
- **删知识库**：从 AGENTS.md 中移除对应行即可
- **调整优先级**：修改 AGENTS.md 中路径的排列顺序
