# Dev Help 快速参考

## 🚀 快速开始

### 何时使用

当你需要:
- ✅ 规划新功能开发
- ✅ 拆解复杂任务
- ✅ 制定开发计划
- ✅ 跟踪项目进度

### 如何触发

**自动触发** - 提到以下关键词:
- "实现XXX功能"
- "添加XXX"
- "修复XXX bug"
- "重构XXX"
- "规划XXX开发"

**手动调用**:
```
@dev-help [你的需求]
```

## 📋 工作流程

```
1. 需求分析 → 2. 信息澄清 → 3. 任务拆解 → 4. 任务确认 → 5. 逐步执行
     ↑              ↑                                              ↓
     └──────────────┘                                    等待用户反馈
   (有不清楚的地方)
```

## 💡 使用技巧

### 提供好需求

**✅ 好的描述**:
```
我需要给组合管理页面添加导出功能:
- 导出当前筛选的数据
- Excel包含:名称、经理、规模、收益率
- 文件名:组合列表_日期.xlsx
- 支持大数据量异步导出
```

**❌ 差的描述**:
```
加个导出功能
```

### 回答澄清问题

当技能提问时:
- 尽量详细回答
- 提供具体选项偏好
- 说明约束条件

### 认真确认任务

检查:
- [ ] 任务是否完整
- [ ] 粒度是否合适(≤2h)
- [ ] 优先级是否合理
- [ ] 时间估算是否准确

### 灵活调整

随时可以:
- "合并Task 3和4"
- "Task 2应该优先"
- "这个任务需要3小时"
- "暂停,我要调整需求"

## ⏱️ 任务标准

### 时间要求

- **每个任务**: ≤ 2小时
- **过大**: 继续拆分
- **过小**(<30min): 考虑合并

### 复杂度评估

每个任务从四个维度评分(1-3分):

| 维度 | 1分 (简单) | 2分 (中等) | 3分 (复杂) |
|------|-----------|-----------|----------|
| **技术** | <100行,熟悉 | 100-300行,基本熟悉 | >300行,需学习 |
| **业务** | <3分支,<5状态 | 3-8分支,5-15状态 | >8分支,>15状态 |
| **依赖** | 0-1外部,0-2内部 | 2-3外部,3-5内部 | >3外部,>5内部 |
| **测试** | <5用例,简单Mock | 5-15用例,中等Mock | >15用例,复杂Mock |

**总分映射**:
- 4-5分 → 0.5-1h
- 6-7分 → 1-1.5h
- 8-9分 → 1.5-2h
- 10-11分 → 建议拆分
- 12分 → 必须拆分

**风险评估**:
- 🟢 低风险: +10%缓冲
- 🟡 中风险: +20%缓冲
- 🔴 高风险: +50%缓冲或预研

📖 详细评估方法: [complexity-assessment.md](references/complexity-assessment.md)

### 验收标准

每个任务必须包含:
- [ ] 明确的交付物
- [ ] 可验证的标准
- [ ] 涉及的文件列表
- [ ] 依赖关系

### 示例任务

```markdown
### Task 1: 实现导出API (1.5h)

**描述**: 创建组合数据导出接口

**文件**:
- `src/api/combination.ts`
- `src/types/combination.ts`

**验收**:
- [ ] 支持分页参数
- [ ] 返回Excel文件流
- [ ] 完整的TypeScript类型
- [ ] 错误处理完善

**依赖**: 无
```

## ❓ FAQ

**Q: 为什么限制2小时?**  
A: 平衡完成度和可估算性,便于跟踪和调整

**Q: 实际超时怎么办?**  
A: 正常现象,暂停分析原因,必要时重新拆解

**Q: 能跳过确认吗?**  
A: 不建议,但可以说"不用确认,直接执行"

**Q: 中途能改需求吗?**  
A: 可以,暂停→说明新需求→重新拆解

**Q: 如何看历史进度?**  
A: `@progress-tracker 查看项目进度`
