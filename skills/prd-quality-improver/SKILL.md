# PRD 质量提升引擎

**目标：** 通过测试用例和代码实现的反馈，反向发现 PRD 的不足，提升 PRD 规范性和边界场景完整性，并检查前后端职责划分是否清晰。

## 覆盖场景

| 场景 | 输入 | 输出 |
|------|------|------|
| 场景1: PRD 版本迭代 | PRD v1, v2, v3... | 版本 diff + 分析质量改进报告 |
| 场景2: PRD+测试→PRD改进 | PRD + 测试用例 | PRD 规范性评估 + 改进建议 |

## 执行环境规范

### 临时工作目录

**所有中间产物必须在临时目录中生成**，不污染项目源码和 skill 目录。

```text
<项目根目录>/.temp/prd-quality-improver-<YYYYMMDD-HHMMSS>/
```

### 环境感知

每次执行前，**必须先检测并记录当前环境信息**（操作系统、项目根目录、执行时间、Shell 类型），保存为 `.env.json` 放在临时目录根。

### 最终输出物保存位置

最终输出物**不保存在 skill 目录中**，而是保存到项目目录：`docs/quality-loop/<YYYYMMDD>/prd-improvement.md`。

### 清理规范

任务结束后**必须执行清理**：将最终输出物转移到项目目录 → 删除整个临时目录 → 输出清理确认日志。

### 异常处理

- 中断或失败时，临时目录**保留**（不清理），便于排查
- 保留 `.status.json` 记录执行状态（running / success / failed）

## Phase 1: PRD 版本对比分析（场景1）

### 输入

```text
docs/prd/v1/订单模块.md   (或 git tag: prd-v1.0)
docs/prd/v2/订单模块.md   (或 git tag: prd-v2.0)
docs/prd/v3/订单模块.md   (当前版本)
```

### 版本 Diff 分析

```markdown
# PRD 版本对比报告

## 版本信息

| 版本 | 日期 | 变更摘要 | 规则数变化 |
|------|------|---------|-----------|
| v1.0 | 2026-06-01 | 初始版本 | 15 条规则 |
| v2.0 | 2026-06-15 | 增加退款流程 | +8 条规则, +3 状态迁移 |
| v3.0 | 2026-07-01 | 完善异常处理 | +5 条降级规则, 修改2条边界 |

## 规则变更追踪

### 新增规则（v1→v2）

| 规则ID | 规则描述 | 引入原因 | 验证状态 |
|--------|---------|---------|---------|
| R016 | 退款需管理员审批 | 安全需求 | ✅ 已有代码实现 |
| R017 | 退款金额 <= 实付金额 | 计算约束 | ✅ 已有测试覆盖 |

### 修改规则（v2→v3）

| 规则ID | v2 描述 | v3 描述 | 变更原因 | 影响范围 |
|--------|--------|--------|---------|---------|
| R004 | 满99免运费 | 满99免运费（含优惠券抵扣前金额判断） | 边界歧义 | 计算逻辑+测试 |

### 删除规则

| 规则ID | 原描述 | 删除原因 | 是否安全 |
|--------|--------|---------|---------|
| R012 | 运费险自动赠送 | 业务调整 | ✅ 代码已移除 |

## 分析质量改进度量

| 指标 | v1 | v2 | v3 | 趋势 |
|------|----|----|-----|------|
| 规则明确度 | 60% | 75% | 92% | ↑ |
| 边界场景覆盖 | 40% | 65% | 85% | ↑ |
| 异常处理覆盖 | 20% | 50% | 80% | ↑ |
| 待确认问题数 | 12 | 6 | 2 | ↓（好） |
| 隐性规则显性化 | 0 | 3 | 7 | ↑ |
```

### 版本对比策略

```
1. 结构化提取每个版本的规则集合
2. 计算规则集合的 diff（新增/修改/删除）
3. 对每条变更规则：
   - 是否有对应代码实现？
   - 是否有对应测试用例？
   - 变更原因是否记录在 PRD 中？
4. 生成版本演进趋势图
5. 识别"改进速度"（每版本提升的覆盖度）
```

## Phase 2: 测试→PRD 改进建议（场景2）

### 输入

- PRD 文档（当前版本）
- 测试用例文件（已有测试）
- 可选：历史 Bug 列表

### 分析流程

```
测试用例 → 提取测试覆盖的业务场景
  ↓
与 PRD 规则比对 → 发现 PRD 缺失/模糊之处
  ↓
生成 PRD 改进建议
```

### PRD 质量评估维度

| 维度 | 评估方式 | 评分标准 |
|------|---------|---------|
| **完整性** | PRD 规则数 vs 测试覆盖的场景数 | 测试场景数 > PRD 规则数 → PRD 不完整 |
| **明确性** | PRD 中"可能"、"建议"、"尽量"等模糊词数量 | 模糊词越多 → 明确性越差 |
| **边界覆盖** | 测试中的边界值 vs PRD 中的边界描述 | 测试有但 PRD 无 → PRD 边界缺失 |
| **异常覆盖** | 测试中的异常路径 vs PRD 中的异常描述 | 测试有但 PRD 无 → PRD 异常遗漏 |
| **一致性** | PRD 内部规则间是否有矛盾 | 规则冲突 → 一致性差 |
| **可测试性** | 每条规则是否可生成测试用例 | 不可测试 → 规则描述不清 |

### PRD 改进报告模板

```markdown
# PRD 质量改进报告

**PRD 文件:** docs/prd/订单模块.md
**测试文件:** test/order/
**评估时间:** 2026-07-09

## 质量评分

| 维度 | 评分 | 说明 |
|------|------|------|
| 完整性 | 72/100 | 5个测试场景在 PRD 中无对应描述 |
| 明确性 | 85/100 | 3处模糊表述 |
| 边界覆盖 | 60/100 | 8个边界值仅3个在 PRD 中明确 |
| 异常覆盖 | 55/100 | 6个异常路径仅2个在 PRD 中描述 |
| 一致性 | 90/100 | 1处规则冲突 |
| 可测试性 | 80/100 | 4条规则难以直接生成测试 |
| **综合** | **74/100** | |

## 改进建议（按优先级排序）

### 🔴 P0: 必须补充（影响功能正确性）

#### 建议1: 补充并发场景描述

**发现来源:** 测试用例 `should_handle_race_condition`
**PRD 现状:** 未提及并发处理
**建议补充:**

```markdown
## 并发安全
- 支付回调与超时取消可能同时触发，系统需保证只有一个操作生效
- 重复的支付回调需幂等处理
```

**对应测试:**
- `SM009: should_handle_payment_and_timeout_race_condition`
- `SM010: should_handle_duplicate_payment_callback_idempotently`

#### 建议2: 明确优惠券超额处理规则

**发现来源:** 测试用例 `should_cap_coupon_at_total_amount`
**PRD 现状:** "优惠券面额不能超过商品总额" — 但未说明超过时如何处理
**建议补充:**

```markdown
当优惠券面额超过商品总额时：
- 实际抵扣金额 = 商品总额（超出部分作废，不找零）
- 实付金额 = 运费（如有）
```

### 🟡 P1: 建议补充（影响边界完整性）

#### 建议3: 补充金额边界值定义

**发现来源:** 测试用例中的 0 元订单、99 元临界值
**PRD 现状:** 未明确定义以下边界
**建议补充:**

```markdown
## 边界值定义
- 0 元订单：允许创建，实付 = 运费
- 99 元订单：恰好满足免运费条件
- 98.99 元订单：不满足免运费条件
- 6个月前的订单：含当天（>= 6个月前的今天 00:00:00）
```

#### 建议4: 补充退款后库存处理

**发现来源:** 测试覆盖中未找到库存回滚逻辑
**PRD 现状:** 退款流程中未提及库存
**建议补充:**

```markdown
退款成功后：
- 已扣减的库存需回滚
- 优惠券需退回（如未过期）
```

### 💡 P2: 优化建议（提升可维护性）

#### 建议5: 消除模糊表述

| 位置 | 原文 | 问题 | 建议修改 |
|------|------|------|---------|
| L45 | "尽量在30分钟内完成支付" | "尽量"不明确 | "必须在30分钟内完成支付，超时自动取消" |
| L78 | "建议设置合理的超时时间" | "建议"无约束力 | "超时时间为30分钟，可配置" |

#### 建议6: 统一术语

| 不一致术语 | 出现位置 | 建议统一为 |
|-----------|---------|-----------|
| "实付金额" / "实际支付" / "应付金额" | L12, L45, L67 | "实付金额" |
| "优惠券" / "优惠劵" / "折扣券" | L23, L49, L71 | "优惠券" |
```

### 测试→PRD 映射分析

```
对每个测试用例：
├── 能映射到 PRD 规则？
│   ├── 是 → PRD 完整 ✅
│   └── 否 → PRD 遗漏 ❌ → 生成补充建议
├── PRD 有描述但模糊？
│   ├── 是 → 明确性不足 ⚠️ → 生成改进建议
│   └── 否 → PRD 明确 ✅
└── 测试覆盖了 PRD 未提及的边界？
    ├── 是 → 边界遗漏 ❌ → 生成边界补充建议
    └── 否 → 边界完整 ✅
```
