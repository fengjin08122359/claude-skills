# PRD 结构化分析

**目标：** 将自然语言 PRD 转化为可计算、可比对的结构化规约。

## 触发时机

- 收到新的 PRD 文档需要评审
- PRD 发生变更需要重新分析
- 需要生成测试用例前
- 代码审查前需要需求基线

## 分析流程

### Phase 1: 文档预处理

```
输入 PRD (Markdown) → 解析结构 → 识别需求段落 → 分类标记
```

**分类标记规则：**

| 关键词模式 | 分类 | 提取模式 |
|-----------|------|---------|
| "计算"、"等于"、"公式"、"金额"、"合计" | 计算规则 | 规则元组 |
| "状态"、"流转"、"变为"、"切换"、"超时" | 状态机 | 状态迁移表 |
| "列表"、"查询"、"展示"、"排序"、"分页" | 查询规则 | 隐性规则显性化 |
| "必须"、"禁止"、"不允许"、"如果…那么" | 约束条件 | 约束规则 |
| "异常"、"失败"、"降级"、"默认"、"兜底" | 异常处理 | 降级规则 |

### Phase 2: 模式提取

#### 模式1: 规则元组提取

**输入段落示例：**
> "订单实付金额 = 商品总额 - 优惠券抵扣 + 运费，运费根据收货地址动态计算，且实付金额不得小于0。"

**提取过程：**

```
步骤1: 识别等式关系 → 计算公式
步骤2: 识别函数映射 → 运费 = f(地址)
步骤3: 识别约束条件 → 实付 >= 0
步骤4: 识别异常处理 → 地址为空时的降级
```

**输出：**

```json
{

    {
      "id": "R001",
      "description": "实付金额 = 商品总额 - 优惠券抵扣 + 运费",

      "formula": "payable = total - coupon + shipping",
      "constraints": [],
      "priority": "P0"
    },
    {
      "id": "R002",
      "description": "运费根据收货地址动态计算",
      "type": "function_mapping",
      "input": "address",
      "output": "shipping_fee",
      "constraints": ["address != null"],
      "priority": "P0"
    },
    {
      "id": "R003",
      "description": "实付金额不得小于0",
      "type": "boundary_constraint",

    },

    }
  ]
}
```

#### 模式2: 状态迁移表提取

**输入段落示例：**
> "订单支付后，状态从'待支付'变为'已支付'，若30分钟未支付则自动取消。"

**提取过程：**

```
步骤1: 识别状态节点 → 待支付、已支付、已取消
步骤2: 识别迁移动作 → 支付成功、超时取消
步骤3: 识别触发条件 → 支付回调、T+30min
步骤4: 推导非法迁移 → 已支付→已取消(非法)
步骤5: 识别并发风险 → 同时到达的竞态
```

**输出：**

```json
{

    "name": "order_payment",

    "transitions": [

        "condition": "amount_match",
        "legal": true
      },
      {
        "from": "待支付",
        "to": "已取消",
        "trigger": "超时30分钟",
        "condition": "auto",
        "legal": true
      },
      {
        "from": "已支付",
        "to": "已取消",

  }
}
```

#### 模式3: 隐性规则显性化

**输入段落示例：**
> "用户查看订单列表，默认按时间倒序，仅展示最近3个月的订单。"

**提取过程：**

```
步骤1: 提取显性规则 → 排序、过滤
步骤2: 推导隐性规则 → 分页、索引、权限
步骤3: 评估性能风险 → 数据量、查询效率
步骤4: 标记验证方式 → 索引检查、分页上限
```

**输出：**

```json
{

      "sql": "ORDER BY create_time DESC",

    {

    },
    {

```

### Phase 3: 异常处理逻辑提取

**通用异常模式识别：**

| PRD 关键词 | 异常类型 | 预期处理 | 验证方式 |
|-----------|---------|---------|---------|
| "如果…那么…" | 条件分支 | 分支覆盖 | 单元测试 |
| "超时" | 超时异常 | 重试/降级 | 集成测试 |
| "并发" | 竞态条件 | 锁/幂等 | 并发测试 |
| "为空" | 空值异常 | 默认值/报错 | 边界测试 |
| "不允许" | 非法操作 | 拦截+提示 | 权限测试 |
| "网络异常" | 网络故障 | 重试+降级 | 故障注入 |
| "数据不一致" | 数据异常 | 事务回滚 | 数据完整性测试 |

## 质量检查清单

分析完成后自检：

- [ ] 所有 PRD 中的"必须"、"禁止"是否都提取为约束规则？
- [ ] 所有数值范围是否都有边界值？
- [ ] 所有状态流转是否都列出了合法/非法迁移？
- [ ] 所有外部依赖是否都有降级策略？
- [ ] 所有列表查询是否检查了分页和索引？
- [ ] 是否有并发场景需要处理竞态？
- [ ] 待确认问题是否已标记并通知产品？

## 与下游技能的衔接

- **→ coverage-matrix：** 分析结果作为矩阵的 PRD 轴
- **→ test-generation：** 每条规则/边界/异常生成对应测试
- **→ code-review-checklist：** 规则和约束转化为审查项
